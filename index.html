Chapter 1 — Apache Spark: Distributed ETL

Spark is a distributed data engine. In this project, Spark was a project constraint, but it also fits the job: thousands of image files, metadata extraction, partitioned writes, and scalable ETL. The project runs with master=local[2] and uses DataFrame API only.

  • Architecture: Driver plans jobs, Executors run tasks on partitions.
  • Lazy evaluation: .filter() and .withColumn() are transformations; Spark executes when an action appears (.count(), .write.parquet()).
  • Image loading: spark.read.format("binaryFile") ingests raw PNG files with path and bytes metadata.
  • Partitioning: Bronze/Silver by pathology + modality; TFRecord export by split + shard_id; 8 Spark partitions used in ETL steps.
  • Shuffle cost: the label mapping join in preprocess may trigger shuffle; expensive because data moves between partitions.
  • Parquet advantage: columnar, compressed, supports predicate pushdown, and can store processed PNG bytes as BinaryType.
  • mapPartitions(): transform_job processes records image-by-image with Pillow inside each partition efficiently.

Key oral point: Spark here is both a mandatory technology and a valid distributed ETL choice for image manifests and format conversion.

Chapter 2 — ML & CNN with TensorFlow

A neural network is a stack of layers that learns patterns from examples. A CNN is specialized for images: convolution filters detect local patterns, BatchNorm stabilizes training, and pooling compresses spatial dimensions.

  • Classifier architecture: Input (224×224×1) → Conv(32) → BN → MaxPool → Conv(64) → BN → MaxPool → Conv(128, final_conv_features) → BN → MaxPool → GAP → Dense(512) → Dropout(0.5) → Dense(15, softmax).
  • Hyperparameters: Adam lr=0.001, batch size=32, max epochs=50, SparseCategoricalCrossentropy, SparseCategoricalAccuracy.
  • Data pipeline: interleave(cycle_length=16) → shuffle(2048) → map(parse) → repeat → batch(32) → prefetch(AUTOTUNE).
  • Generalization reading: val 73.7% vs test 68.6% indicates mild overfitting (not catastrophic).
  • Callbacks: EarlyStopping(patience=10, restore best weights) and ModelCheckpoint(save_best_only, monitor val_accuracy).

Chapter 3 — Data Pipeline (Bronze / Silver / TFRecord)

The Bronze/Silver pattern keeps raw provenance separate from transformed data. Bronze stores traceable metadata from raw files. Silver adds standardized 224×224 grayscale bytes, ready for deterministic splitting and export.

  • Bronze columns: image_id (SHA-256), raw_path, pathology, label_idx, modality, file_size.
  • Silver columns: Bronze + processed_bytes, processed_file_size, orig_width, orig_height, new_width, new_height, channels, transform_version.
  • keep_aspect_pad: convert L mode → thumbnail Lanczos (no stretching) → paste centered on black 224×224 canvas.
  • Split: seed=42 and ratios [0.7, 0.15, 0.15] ≈ 3,135 train / 672 val / 672 test from 4,479 images.
  • TFRecord export: each example stores image_bytes + label_idx; 16 shards partitioned by split and shard_id.
  • Why TFRecord: efficient sequential I/O and better tf.data parallel interleave/prefetch performance than loading individual PNG files.

Chapter 4 — Anomaly Detection (Autoencoder)

An autoencoder learns to reconstruct what it sees during training. Here, it is trained only on _NORMAL scans (441 train+val normal images), so it learns normal anatomy patterns. Unusual cases produce higher reconstruction error.

  • Encoder: Conv32/64/128/256 (stride=2, same, relu) + BatchNorm → Flatten → Dense(128 bottleneck).
  • Decoder: Dense(14×14×256) → Reshape → Conv2DTranspose 128/64/32/1 + BatchNorm → Resizing(224,224), final sigmoid.
  • Loss and optimizer: MSE with Adam(lr=0.001), batch 32, max 50 epochs, EarlyStopping on val_loss with patience 10.
  • Error metric: per-pixel squared difference, then max pixel error per image.
  • Threshold calibration: strict=0.9999 (max of normal max-errors), p99=0.9946, p95=0.9420.

Chapter 5 — Explainability with Grad-CAM

In medical imaging, explainability helps clinicians understand why the model predicts a class. Grad-CAM highlights regions that influenced the predicted class score.

  • Target layer: final_conv_features (3rd Conv2D, 128 filters). If missing, fallback to last 4D layer.
  • Computation: GradientTape on predicted class score → gradients wrt feature maps → spatial mean of gradients → weighted sum of maps → ReLU → normalize to [0,1].
  • Artifact outputs: heatmap PNG + overlay PNG.
  • Overlay rule: 65% original image + 35% red heatmap.

Oral tip: Grad-CAM does not prove causal diagnosis. It provides visual evidence to support model trust and debugging.

Chapter 6 — Code Architecture & Async Inference

The project is modular and config-driven. Spark jobs, TensorFlow training, and async inference are split into dedicated modules under src/, while each job has its YAML config in conf/.

  • Config-driven: train.yaml and train_anomaly.yaml define batch size, epochs, learning rate, patience, latent_dim and normal class.
  • Async flow: upload → status.json=pending → worker polling every 2s → queued → resolving_input → building_bronze → building_silver → running_inference → writing_results → done/failed.
  • Worker outputs: result.json, predictions.parquet, Grad-CAM and reconstruction artifacts.
  • Model registry: centralized loading of .keras models and threshold JSON files.
